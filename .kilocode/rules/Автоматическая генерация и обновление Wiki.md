# 1. **Назначение агента**

ИИ-агент автоматически анализирует изменения в кодовой базе после каждого коммита и поддерживает проектную Wiki в актуальном состоянии:

- создает новые страницы,
- обновляет существующие,
- удаляет или архивирует устаревшие,
- поддерживает структуру, ссылки, оглавление,
- сохраняет историю изменений документации.

Wiki всегда должна отражать **реальное состояние проекта на текущем коммите**.

---

# 2. **Триггеры**

Агент запускается:

- после каждого коммита в основной или указанной ветке,
- по ручной команде (например, `regen-wiki`),
- при массовых структурных изменениях (rename, refactor, перемещение модулей).

---

# 3. **Область ответственности**

Агент работает только с:

- исходным кодом (`src/`, `app/`, `server/`, `api/`, `client/`, `components/`)
- конфигурациями (`config/`, `*.config.*`)
- схемами данных (`schema/`, `models/`)
- роутами и контроллерами
- сервисами и утилитами
- документацией (`docs/`, `wiki/`)

## Игнорируются полностью:

- `node_modules`, `vendor/`
- `dist/`, `build/`, `.next/`, `.output/`
- временные и генерируемые файлы
- тестовые файлы (`*.spec.ts`, `*.test.js`)
- мок-данные
- статические ассеты

---

# 4. **Общая логика работы агента**

## 4.1. Получение diff

Агент извлекает:

- список изменённых файлов,
- список новых файлов,
- список удалённых файлов,
- содержимое изменений.

## 4.2. Определение типа файла

Тип определяется по пути + содержимому:

| Признак                     | Тип                  |
| --------------------------- | -------------------- |
| /api/, /routes/, `route.ts` | API endpoint         |
| /services/, /usecases/      | сервис/бизнес-логика |
| /models/, /schema/          | модель данных        |
| /components/                | UI компонент         |
| util, helper                | утилита              |
| config                      | конфигурация         |

## 4.3. Определение нужных действий

- **Файл создан →** создать новую страницу в wiki
- **Файл изменён →** обновить существующую страницу
- **Файл удалён →** пометить страницу как `DEPRECATED` и переместить в архив
- **Файл перемещён (git rename) →** обновить путь + ссылки

# 5. **Формализованный шаблон wiki-страницы**

Каждая страница **строго** следует этому шаблону:

```
# {Название модуля}
Путь: `{полный путь до файла}`

## Назначение
Краткое описание (1–3 предложения), понятное новичку.

## Интерфейс

### Входные данные
- параметры функции / endpoint (типы, DTO, схемы)
- query / body / headers (для API)

### Выходные данные
- тип возвращаемого значения
- структура успешного ответа
- возможные ошибки и их причины

## Логика работы (коротко)
5–12 предложений простым языком: что делает модуль и как.

## Где используется
Список файлов, импортирующих данный модуль (если применимо).

## Примечания
Важные детали, бизнес-правила, edge-cases.

## Источник изменений
- Последний изменивший коммит: `{hash}`
- История изменений: список (при наличии)
```

Минимальная длина страницы: **не менее 8 строк**.  
Строго запрещено: вода, общие фразы, неопределённые описания.

---

# 6. **Правила формирования названий страниц**

Название формируется по шаблону:

```
{категория}-{имя-файла-без-расширения}.md
```

Категория определяется по директории:

- API → `api-*`
- Component → `component-*`
- Module/Service → `module-*`
- Model/Schema → `model-*`
- Util → `util-*`

Примеры:

- `/src/api/auth/login/route.ts` → `api-auth-login.md`
- `/src/services/user/updateProfile.ts` → `module-updateProfile.md`
- `/src/components/Button.tsx` → `component-button.md`

---

# 7. **Структура Wiki**

Агент обязан поддерживать структуру директорий:

```
/wiki
  /api
  /modules
  /services
  /components
  /models
  /utils
  /config
  /deprecated
  index.md
```

Файл `index.md` содержит:

- оглавление,
- список всех страниц,
- категории,
- ссылку на Changelog.

---

# 8. **Работа с устаревшими файлами**

Если файл **удалён** из проекта:

1. страница перемещается в `/wiki/deprecated/`
2. в начало файла добавляется:

```
> ⚠️ Данный модуль удалён из проекта.
> Дата удаления: {дата}
> Коммит: {hash}
```

3. все ссылки на него помечаются как устаревшие.

---

# 9. **Анализ и извлечение информации из кода**

Агент обязан:

- парсить типы и интерфейсы (TS/JS)
- вытаскивать JSDoc
- извлекать схемы из `zod`, `yup`, `class-validator`
- анализировать маршруты API
- определять входные/выходные данные функций

Если назначение файла неочевидно — агент пишет:

```
Назначение определено по структуре и экспорту файла, так как явной логики нет.
```

---

# 10. **Правила стиля**

- Писать кратко, без воды
- Использовать простой язык
- Не использовать сложные абстракции
- Ориентироваться на новичка
- Все примеры должны быть основаны на реальном коде
- Строго избегать «общей воды» — объясняется только конкретный функционал

Запрещено:

- Lorem ipsum-фразы
- Высокоуровневый маркетинговый текст

---

# 11. **Changelog документации**

Агент обязан генерировать файл:

```
/wiki/changelog.md
```

Каждый запуск добавляет запись:

```
## {Дата, время}
Коммит: {hash}

- Добавлено: список страниц
- Обновлено: список страниц
- Перемещено: список
- Удалено / архивировано: список
```

---

# 12. **Валидация и проверка перед записью**

Перед обновлением wiki агент должен проверить:

- нет ли дублей страниц
- корректна ли структура директорий
- все ссылки валидны
- шаблон страницы соблюдён
- нет ошибок форматирования
- JSON/YAML/TS-схемы корректно отображены

Если есть ошибка — агент **корректирует автоматически**.

---

# 13. **Политика безопасности**

Агент строго запрещено включать:

- содержимое `.env` и любых секретов
- ключи API
- приватные токены
- пароли
- приватные сертификаты
- логины пользователей

Если такие данные встречаются в diff — игнорировать + пометить в changelog:

```
⚠️ Секретные данные скрыты автоматически.
```

---

# 14. **Финальный регламент поведения агента**

## При создании файла:

- создать новую страницу
- добавить в оглавление
- занести в changelog

## При изменении файла:

- обновить страницу
- сохранить историю изменений
- обновить оглавление (если изменилось название)

## При удалении файла:

- переместить страницу в `/deprecated/`
- обновить оглавление
- занести в changelog

## При перемещении:

- обновить путь в wiki
- обновить cross-links
- обновить changelog
